### Optimisation — `-Dsingle-pool` build flag

Comptime-elides the F-001 pool-identity check on the hot submit path.
Reliably recovers 6–17% on `contended_spawn_8x`, `cpu_work_100us`, and
`mixed_fast_slow`.

```bash
# Safe default (multi-pool capable):
zig build

# Opt-in single-pool optimisation (UNSAFE with >1 pool per process):
zig build -Dsingle-pool=true
```

## Followups (not yet picked up)

Listed in [`FINAL.md § Recommended follow-ups`](performance/appsec-fixes-2026-04-15/FINAL.md#recommended-follow-ups).
The remaining open items:

1. Investigate `flood_1m` −7.2% — the `-Dsingle-pool` flag does not
   recover this scenario. Likely LLVM reorder inhibition around the
   F-003 `.monotonic` freelist accesses. A stronger single-producer
   contract would allow eliding the atomics behind a build flag.
2. CI catalog images bump from 0.15.2 to 0.16.0. Currently the TSan
   jobs install 0.16.0 inline; the catalog-driven tests pin 0.15.2
   and are running against a 0.16-only codebase, which will fail on
   next CI run. Fixing this requires either updating the catalog
   component or swapping to direct `install-zig.sh` for all jobs.
3. Expanded bench sample counts — the single-run `bench-runtime-compare`
   has up to 19% CV on some scenarios, which made several optimisation
   deltas inconclusive. A multi-run aggregator with stronger statistics
   would improve future perf-gate signal.
